# AGENTS.md

## Project

ParamEx is a pure Rust Windows desktop app for TFT characterization. The Cargo
workspace contains two crates:

- `paramex-core`: GUI-free Transfer, TLM, Model Fit, parsing, science, and export.
- `paramex-gui`: the egui/eframe desktop app and its tests.

`paramex-gui` is the only runnable binary. Do not add Python runtime or installer
requirements.

## Architecture

- Import product behavior through `paramex_core::{transfer, tlm, modelfit}`.
- Put a primitive in `paramex_core::shared` only when multiple current products
  consume it.
- Keep GUI behavior under the owning `workspaces/{transfer,tlm,modelfit}` seam.
- Core owns scientific validation and state transitions; the GUI owns selection,
  presentation, ingest effects, and recoverable pending data.
- Invalid inputs, failed fits, and weak fits remain visible. Never discard or hide
  inconvenient measurements.
- `numpy_compat` is parity-critical and requires focused reference tests.

Test-data terms:

- `fixture`: an ordinary raw test input.
- `reference`: committed expected data.
- `oracle`: expected data regenerated by an in-tree Rust generator.

All committed test data must be synthetic and regenerable.

## GUI Contract

- Same task, same interaction across Transfer, TLM, and Model Fit.
- Empty and loaded states share one render path; loading data must not move fixed
  controls, headers, or summary columns.
- Numeric labels stay left of their inputs. Numeric fields use the shared UI kit,
  native single-line height, right alignment, and the standard compact width.
- Errors persist in the workspace as well as appearing in a toast.
- Only list/table/plot bodies scroll; their headers and actions stay fixed.
- Model Fit always shows its four validation plots and two gm/Id design plots.
- Characterization plots display positive `|I_D|`; signed core data and exports
  remain unchanged.
- TLM labels the fitted intercept as `intercept (2R_c)` and the derived value as
  `R_c/contact`.
- Hand-painted controls require pointer-driven tests.
- Pixel changes require exact layout/overflow guards and refreshed empty+loaded
  snapshot pairs.

Do not rename the user-facing `Transfer`, `TLM`, or `Model Fit` workspaces.

## Commands

Run from the repository root:

```powershell
cargo fmt --all --check
cargo test --workspace --no-fail-fast
cargo clippy --workspace --all-targets -- -D warnings
cargo test -p paramex-core --test transfer
cargo test -p paramex-gui --test app_snapshot
cargo run -p paramex-gui
.\packaging\windows\build-local-dist.ps1
```

## Definition Of Done

1. Formatting, full workspace tests, and Clippy pass.
2. Pixel changes pass snapshots plus exact layout and overflow guards.
3. Interactive custom widgets have a real pointer/keyboard state test.
4. Deleted or renamed files leave no stale references.
5. The packaged `ParamEx.exe` starts and stays below the 15 MiB release gate.
6. The working tree contains no `.old.png`, build output, or unrelated changes.

Do not tag or push unless the user explicitly asks.

## Release

The crate version and `vX.Y.Z` tag must match. The release workflow publishes one
unsigned Windows ZIP containing `ParamEx.exe`, the MIT `LICENSE`, and generated
third-party dependency notices.
